10-Minute Final Presentation: Multi-Agent Autonomous Workflow
Slide 1 — Problem (1:00)
Goal: Add a Planner → Researcher → Coder → Reviewer autonomous workflow to CUGA using LangGraph, with guardrails, persistence, and an HTTP API — without touching existing agent code.

Why it matters: CUGA had single-agent (CugaLite) and supervisor (CugaSupervisor) patterns, but no collaborative multi-agent graph with human-in-the-loop approval for risky actions.

Scope: Additive only — new files under src/cuga/backend/cuga_graph/nodes/multi_agent/, extended AgentState, new settings, new FastAPI routes, new tests, new docs.

Slide 2 — Design (2:00)
Four agents (agents.py):

Planner → ExecutionPlan (subtasks, deps, risk, approval reqs)
Researcher → ResearchResult[]
Coder → sandboxed Python via run_code()
Reviewer → ReviewOutput (approve/revise/reject)
Graph (workflow.py): LangGraph StateGraph over extended AgentState; conditional edges route on review outcome; interrupt pauses risky actions.

Guardrails (guardrails.py): LoopDetector (repeat detection), BudgetTracker (iterations, tokens, cost, time, consecutive rejections).

Persistence + tracing (workflow_persistence.py, workflow_tracer.py): PostgreSQL tables (workflow_runs, agent_executions, approval_history, tool_execution_history) + OTel spans.

API (workflow_routes/__init__.py): /api/workflow/run | state | approve | history | approvals | plan, mounted in main.py:2453.

Config: [multi_agent_workflow] section in settings.toml + Validator() entries in config.py.

Code to show: schemas.py:41-102 (Subtask/ExecutionPlan), workflow.py graph assembly, guardrails.py:17-74 (LoopDetector/BudgetTracker classes).
